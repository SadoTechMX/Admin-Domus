# Isolated audited release v4 (development contract, not deployment approval)

All new routes use the original CAJA session and native staging transport, original requestId, original body, original device/operator. No outbox, login renewal, retries, generic idempotency, journal resume, opening, sale or printing. Administrative manager approval is a private server property, no public setter.

Base input: same as consultarAperturaQa plus originalAttemptHash (sha256 canonical raw string). localEvidenceHash remains the digest of qaUnconfirmedCapture_.seal. Build is the paired source hash.

Routes:
- prepararLiberacionQa: read-only proposal, requires durable confirmed ACK. Returns {ok:true, kind:'QA_RELEASE_PROPOSAL_V1', evidence, evidenceHash, ack, canRelease:false, canRetry:false, financialFinal:false}. Evidence fields: version, protocol='QA_AUDITED_RELEASE_V1', mode='EXISTING_ACK'|'RECOVERED_ACK', requestId,payloadHash,deviceId,operator,principal,localEvidenceHash,originalAttemptHash,backendSourceSha256,projectId,mainSheetId,opsSheetId,ackHash,ledgerHash,journalHash,boundarySnapshotHash,policyHash,inventoryHash,recoveryGateHash (null or hash).
- reservarLiberacionQa: explicit administrative reservation, same input plus approvalId,confirmEvidenceHash,confirmReserve:true. Requires exact configured Gerencia approval and installs PREPARED barrier. Returns ticket below. Client writes reserve intent before RPC. No retries on uncertain response; query instead.
- consultarLiberacionQa: read-only same input plus approvalId,confirmEvidenceHash; returns matching ticket or error (never creates). Can recover lost reserve/commit response. Durable ACK must still validate.
- confirmarLiberacionQa: same input plus approvalId,confirmEvidenceHash,ticketId,archiveHash,confirmArchive:true,confirmRelease:true. Requires PREPARED ticket, same snapshot, approval current, valid archive digest. Only one property transitions to RELEASED_AUDITED. No request/journal/business writes. No automatic retry. Returns ticket/receipt below.

Ticket/receipt projection exact keys: ok,kind='QA_AUDITED_RELEASE_TICKET_V1',state='PREPARED'|'RELEASED_AUDITED',ticketId,evidenceHash,approvalId,requestId,payloadHash,deviceId,backendSourceSha256,originalAttemptHash,localEvidenceHash,ack,ackHash,recoveryGateHash,preparedAt (ISO),expiresAt (epoch milliseconds),archiveHash,committedAt,receiptHash,canOperate,financialFinal. PREPARED: archiveHash/committedAt null, canOperate false. RELEASED: archiveHash64, committedAt ISO, canOperate true. receiptHash hashes the complete projection with receiptHash omitted, canonical digest. No secrets or arbitrary fields accepted. Max serialized projection 30k. ticketId64 is deterministic hash of {protocol:'QA_AUDITED_RELEASE_V1',evidenceHash,approvalId,requestId}. expired PREPARED never clears itself or permits replay.

Client must archive byte-for-byte hold, snapshots, original UNCONFIRMED attempt, observation/recovery if any and snapshot values, plus proposal and PREPARED ticket before commit, read back and hash. Original attempt must not be rewritten CONFIRMED. Append-only archive and separate resolution record, no blanket cleanup. Finalization requires matching server RELEASED receipt and archive digest, preserves unrelated keys/intents, then singleton cleanup + receipt + hold removal under traffic/store locks. On any failure retain evidence/hold and allow only explicit ticket query/finalization, not retry opening or commit. Archive/receipt may survive local partial cleanup; exact resumable prefix checks required. operational client adds qaReleaseTicketId envelope ONLY from verified active resolution record after finalization. Server allows only ticket-bound device/operator/principal/build; all other stations and older clients lacking envelope remain blocked. Existing recovery gate remains unchanged; missing/changed gate blocks.

LocalStorage is not immutable and browser/server commit is not atomic. Administrative barrier against old or external writers is a verified external precondition, not proven by a boolean/hash. Actual Google latency and browser tests need an authorized environment. No publication/deployment/live action is authorized by this document.

Compatibility: gate from an older backend build is NOT migrated or authorized by this candidate. RECOVERED_ACK refers to the v3 recovery algorithm executed in this same paired v4 build. Production deployment remains forbidden. Missing/deleted release property by an administrator is outside the client/lock threat model; no supported endpoint deletes it. Server clock and property integrity are trusted platform inputs. Property record is capped at 8500 UTF-8 bytes before reservation/commit.
